# Translation Architecture - Quick Reference

## File Overview

**`app/api/reform/generate/route.js`** (MAIN CONTROLLER)
- Entry point for report generation via POST /api/reform/generate
- Orchestrates all translation steps
- Key functions:
  - `translateLabels(lang)` - Translates UI labels object (L) via GPT-5-nano
  - `translateHTML(html, lang)` - Full HTML document translation (non-English only)

**`lib/reportTemplate.js`** (UI LABELS & STRUCTURE)
- `DEFAULT_LABELS` - Object with all UI text labels (prepared for translation)
- `buildReformReportHTML()` - Main template function that assembles the report
- Uses `translatedLabels` (L) object for all visible text
- Key labels:
  - `L.transformationPlan`, `L.preparedFor`, `L.preparedBy`, `L.confidential`
  - Section titles: `L.executiveSummary`, `L.currentState`, etc.
  - Chart labels, table captions

**`lib/worldClassVisuals.js`** (CHARTS & VISUALS)
- Functions: `executiveSummaryInfographicHTML()`, `waterfallChartHTML()`, `radarChartHTML()`, etc.
- These receive a translator function via `setWorldClassVisualsTranslator(t)`
- Translator converts chart labels, axes, legends to target language

**`lib/reportGraphs.js`** (CHART FUNCTIONS)
- `barChartHTML()`, `lineChartHTML()`, `benchmarkHTML()`, etc.
- Receive translator via `setGraphTranslator(t)`
- Uses translator for: titles, axis labels, series names

**`lib/implPlan.js`** (IMPLEMENTATION SECTION)
- Generates implementation timeline and structured data
- Should use `L` labels for all section text

**`lib/implKitHTML.js`** (IMPLEMENTATION KIT RENDERING)
- Renders implementation kit appendices (A-K)
- Uses `L` labels for headers, titles, column names

## Translation Flow (Step-by-Step)

### Step 1: Language Selection (client sends request)
```
POST /api/reform/generate
Body: { lang: "Spanish", orgName: "...", ... }
```

### Step 2: Load Default Labels
```javascript
// route.js - line ~2700
const translatedLabels = await translateLabels(canon.lang);
// translatedLabels = { transformationPlan: "Plan de Transformación", ... }
```

### Step 3: Generate Sections with Language
```javascript
// route.js - genSectionFirstPass()
// AI generates content directly in target language
// Receives language instruction in prompt
```

### Step 4: Translate Labels via GPT-5-nano
```javascript
// route.js - translateLabels()
// Input:  DEFAULT_LABELS object (English)
// Model:  gpt-5-nano (temperature: 1)
// Output: translatedLabels object in target language
```

### Step 5: Build Report with Translated Labels
```javascript
// route.js - buildReformReportHTML()
const html = buildReformReportHTML({
  canon,
  sections,
  translatedLabels,  // <-- Passed here
  worldClassVisuals: {...}
});

// reportTemplate.js - buildReformReportHTML()
// Uses: L = translatedLabels  (from props)
// Renders: ${L.transformationPlan}, ${L.preparedFor}, etc.
```

### Step 6: Translate Full HTML (if non-English)
```javascript
// route.js - line ~3450
if (!/^english$/i.test(canon.lang)) {
  translatedHtml = await translateHTML(html, canon.lang);
}
// This handles any remaining English text in charts, tables, etc.
```

### Step 7: Return Final HTML
```javascript
return NextResponse.json({ ok: true, html: finalizedHtml, ... });
```

## Where Translation Happens

### UI Labels (Title Page, TOC, Section Headers)
- **Source:** `DEFAULT_LABELS` in `reportTemplate.js`
- **Translation:** `translateLabels()` in `route.js` via GPT-5-nano
- **Injection:** `buildReformReportHTML()` uses `L.labelName`
- **Status:** ✅ Should work if labels are in DEFAULT_LABELS

### Chart Titles & Axes
- **Source:** `barChartHTML()`, `lineChartHTML()`, etc. in `reportGraphs.js`
- **Translation:** Via `setGraphTranslator()` in `route.js`
- **Method:** Translator function translates titles/axes on-the-fly
- **Status:** ✅ Wired but depends on translator being passed

### World-Class Visuals (Waterfall, Radar, etc.)
- **Source:** Functions in `worldClassVisuals.js`
- **Translation:** Via `setWorldClassVisualsTranslator()` in `route.js`
- **Method:** Translator passed to each visual function
- **Status:** ✅ Wired

### Section Content (Executive Summary, Current State, etc.)
- **Source:** Generated by `genSectionFirstPass()` in `route.js`
- **Translation:** AI generates directly in target language (language instruction in prompt)
- **Status:** ✅ Should work if language instruction is in prompt

### Tables & Captions
- **Source:** Generated by `injectTableTitles()` and `injectTableTitlesAI()`
- **Translation:** Table titles and content should be translated via `translateHTML()`
- **Status:** ⚠️ Depends on `translateHTML()` working correctly

### Appendices (A-K)
- **Source:** Generated by `genImplKitJSON()`, `genImplementationChecklist()`, etc.
- **Translation:** Content generated directly in target language (language instruction in prompt)
- **Status:** ⚠️ Check if language instruction is present in all appendix generation functions

## Common Issues & Fixes

### Title Page Not Translating
- ❌ Labels not in `DEFAULT_LABELS`
- ❌ `translatedLabels` not passed to `buildReformReportHTML()`
- ✅ Check that `L.transformationPlan`, `L.preparedFor`, `L.preparedBy` exist

### Charts Not Translating
- ❌ Translator not passed via `setGraphTranslator()`
- ❌ `worldClassVisuals` not passed to template
- ✅ Verify `setWorldClassVisualsTranslator()` is called before chart rendering

### Appendices Not Translating
- ❌ Language instruction missing from AI prompts
- ❌ `canon.lang` not passed to appendix generation functions
- ✅ Check `genImplKitJSON()`, `genImplementationChecklist()` have language instruction

### Full HTML Translation Failing
- ❌ `translateHTML()` timing out or hitting API limits
- ❌ HTML too large for single API call
- ✅ Check logs for `translation.complete` or `translation.error`
